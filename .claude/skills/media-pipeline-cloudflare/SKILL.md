# Two-Tier Media Pipeline (Cloudflare Stream & R2) Skill

> **Mandate:** Raw media and high-definition video files MUST NEVER transit through the backend API. The API is strictly an orchestrator of signed upload URLs and cryptographically sealed playback tokens.

---

## 1. Pipeline Architecture (REQUIREMENTS.md Section 3.7)

### Tier 1: Recorded Course Videos (Cloudflare Stream)
1. **Direct Creator Uploads:**
   - Teacher requests an upload slot from the backend API.
   - Backend calls Cloudflare Stream API to generate a Direct Creator Upload URL supporting the **TUS (resumable)** protocol.
   - Frontend uploads video chunks directly to Cloudflare Stream.
2. **Webhook Status Processing:**
   - Cloudflare notifies backend webhook upon successful encoding and ready state.
   - Backend updates video metadata (duration, thumbnail URLs, HLS manifest ID) in the database.
3. **Signed Playback Tokens (Zero Public Video URLs):**
   - Videos are never publicly accessible.
   - When an enrolled student requests playback, backend validates enrollment and generates a **time-limited Signed JWT** (valid for 2 hours) using Cloudflare Stream private signing keys.
   - Adaptive Bitrate (ABR via HLS / DASH) automatically adjusts to user network quality.

### Tier 2: Static Media, Documents & PDFs (Cloudflare R2)
1. **Presigned S3 PUT URLs:**
   - PDFs, slide decks, assignment files, and course thumbnails upload directly to **Cloudflare R2** via presigned S3 URLs generated by backend AWS SDK credentials.
2. **WebP Compression:**
   - Image assets must be compressed to modern WebP format before final upload or delivery.

## Per-tenant feature control (binding, added 2026-09-29)

- Media belongs to tenant features (`video_lessons`, `documents`): new upload/playback/completion endpoints carry `[RequiresFeature]`, and disabling a feature never deletes stored objects or StoredObject ledger rows. Downloads needed to settle existing obligations stay `[CoreFeature]`.
