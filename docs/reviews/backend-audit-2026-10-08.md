## Findings by area

**Authorization and validation.** The reviewed route handlers generally call server-side role guards, and vendor manager queries are scoped by vendor ID. The Microsoft provider does use `oid` as its account subject. The main authorization gap is the explicit admin 2FA exception above. Most request bodies and query parameters use Zod; the logo upload uses manual size, MIME, and signature checks and should be brought under the same validation convention. The administrator-controlled student email regex accepts patterns that may be expensive to evaluate; constrain its syntax or use a bounded matcher. [server.ts](<D:/SU/SU Card/lib/auth/server.ts:35>) · [settings service](<D:/SU/SU Card/lib/settings/service.ts:10>) · [logo route](<D:/SU/SU Card/app/api/admin/vendors/[id]/logo/route.ts:5>)

**Claims and redemptions.** Claiming locks the student and card rows, and confirmation locks the scan row plus a per-student, per-offer advisory key. Those are sound safeguards against common double-claim and double-redemption races. Confirmation is idempotent for a repeated identical request. Validation has no request idempotency key, so retries create extra scan events; batch creation likewise creates another batch on a retried POST. Add operation keys where retries have material effects. The cashier’s “today” endpoint returns every redemption since midnight without pagination. [claim service](<D:/SU/SU Card/lib/student/service.ts:74>) · [scan.ts](<D:/SU/SU Card/lib/vendors/scan.ts:79>) · [batches route](<D:/SU/SU Card/app/api/admin/batches/route.ts:13>)

**Performance and serverless reliability.** Scan validation runs one count query per active offer; fetch the counts for all relevant offers in grouped queries. Student search performs additional home and redemption queries for each result. CSV exports accumulate up to 100,000 rows in memory and use progressively slower `OFFSET` paging. Use grouped queries, keyset pagination, and streaming responses. The Google Wallet `classSynced` flag is per process, so it cannot coordinate Vercel instances. Network calls to Google have no explicit timeout. [scan.ts](<D:/SU/SU Card/lib/vendors/scan.ts:25>) · [admin.ts](<D:/SU/SU Card/lib/student/admin.ts:76>) · [exports.ts](<D:/SU/SU Card/lib/analytics/exports.ts:9>) · [google.ts](<D:/SU/SU Card/lib/wallet/google.ts:105>)

**Caching, email, and tests.** Reviewed scan, claim, and auth decisions read current database state; scan routes force dynamic execution and their JSON responses use `no-store`. The Google Wallet save endpoint also uses `no-store`. Keep these properties in regression tests. Existing tests cover policy and pure rules, but critical database paths lack concurrent claim, quota, session revocation, wallet retry, and mail delivery tests. The written architecture and deployment runbooks still describe a VPS, Redis, Apple Wallet endpoints, and cron workers; reconcile those documents with the stated Vercel and Neon deployment before using them as operational instructions. ## Independent fix tasks

1. **Admin identity and request security** — Own `lib/auth/**`, `next.config.ts`, and `lib/log.ts`. Require verified 2FA for admin access, bound the student email matcher, remove inline-script CSP permission, and sanitize production errors. **Accept when:** Microsoft and password admin flows have passing access tests; disabled and demoted users remain denied; logs contain no input values or secrets.

2. **Claims, scans, and database integrity** — Own `lib/student/service.ts`, `lib/vendors/scan.ts`, `app/api/scan/**`, `app/api/student/card/**`, `lib/db/schema.ts`, and `drizzle/**`. Close claim-rate loopholes, batch offer counts, add the account identity and quota indexes, and add concurrent claim and redemption tests. Include a data check and restore procedure for `0011`; do not rewrite an already applied migration. **Accept when:** repeated claims do not call Google or grow attempts without bound; concurrent tests preserve one active card and each offer quota.

3. **Wallet reconciliation** — Own `lib/wallet/**` and `app/api/student/wallet/**`. Add timeouts and a scheduled reconciliation of issued passes against current student and card state; remove reliance on process-local class synchronization for correctness. **Accept when:** a failed Google call is retried after a new instance starts and a suspended, deleted, or replaced card reaches the correct pass state.

4. **Mail delivery** — Own `lib/email/**` and `app/api/mailer/**`. Authenticate with a header, atomically claim queued mail, record attempts and failures, and make acknowledgement safe to repeat. **Accept when:** two pollers cannot claim one message simultaneously and a failed delivery can be retried without losing its reset link.

5. **Bounded reads and exports** — Own `lib/analytics/**`, `lib/student/admin.ts`, `lib/cards/batches.ts`, `lib/cards/export.ts`, `app/api/admin/batches/**`, and `lib/db/index.ts`. Stream or page large reads, eliminate student-search N+1 queries, and configure the Neon pool and timeouts. **Accept when:** large exports stay within a measured memory and duration budget, search query count stays roughly constant per page, and pooled connections remain bounded under concurrent instances.

This was a **read-only source audit**. No files were edited, and no database or runtime tests were run.
